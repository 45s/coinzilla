## Cohesive-module dispositions

The following codes are explicit keep decisions for the inventory rows:

- KEEP-ADAPTER: one provider BrokerPort adapter; REST/RPC/Streams clients, user-data session, protocol adapters, and capability collaborators are already separate. Keep the public adapter facade; extract only after tests identify a concrete ownership/state boundary.
- KEEP-TRANSPORT: one protocol client/session owns connection, authentication, timeout, request identity, and transport errors; those invariants form one boundary.
- KEEP-PERSISTENCE: one repository/provider/Journal/codec boundary; storage invariants are cohesive and command, codec, or store collaborators are already separate.
- KEEP-WORKFLOW: one serialized state machine/use case; stages share transition, accounting, or readiness invariants, so no independent public service boundary is evidenced.
- KEEP-ALGORITHM / KEEP-STRATEGY: one domain aggregate, calculation, or strategy decision; validation and calculation phases preserve a single domain invariant.
- KEEP-SHUTDOWN: one shutdown participant/coordinator or process lifecycle; phase ordering is part of its safety contract and participants are already separate.
- KEEP-SANDBOX: one process/sandbox security boundary; trusted executable checks, resource limits, and process launch must remain coordinated. Any future private extraction requires direct security tests.
- KEEP-CLI: one operator/reporting CLI; argument parsing, evidence collection, and report output form one command contract.
- KEEP-API / KEEP-INFRA / KEEP-POLICY / KEEP-BROKER-OP: one HTTP API composition, logging service, admission policy, or single broker operation with explicit preflight/readback.
