## S-7 source-tree evidence

The recursive Git tree at `develop` commit `895f3aa4a9ebb93a12dd95168b2e56118cc3173a` contained 1,403 entries, including 1,023 JavaScript files. All 1,023 JavaScript filenames use lowercase kebab-case word segments; 37 also use a dot-separated role/scope qualifier (for example `.port.js` or `.lifecycle.test.js`). 505 files used the workspace's `.test.js` convention and none used `.spec.js`. The tree contained nine `helpers/` directories, four `adapters/` directories, one `services/` directory, two `utils/` directories, and no `common/` or `misc/` directories.

The source layouts intentionally differ: Harvester, Brokers and DB use layers where needed; Entities groups by domain concept; Indicators keeps calculation modules flat; Event Bus, Journal, Notifiers and Utils use smaller package-specific layouts. Harvester has a separate layered `test/` tree for cross-module tests, while package unit tests are generally colocated. These are examples of responsibility-based choices, not a mandatory shared template.

Known exceptions are recorded rather than hidden or mass-refactored: the Binance WebSocket `utils/` directory currently contains clients, transport and protocol responsibilities and is not a pattern to expand; Conservative Strategy has a legacy `helpers.js` aggregation outside the helper-directory scanner's scope; and narrow feature-local `adapter.js` / `constants.js` names rely on their parent directory for context. The single DB `domain/services/` directory contains migration-history policy, not a generic application service bucket. Future moves require focused owner-led PRs with consumer tracing and tests.

## S-4 verified findings — 2026-11-20

The S-4 audit inspected the existing canonical standard, the shared base and representative owner implementations/tests on `develop` at `03339f7d388573947e61e381935b652de202e2e0`.

- **Shared contract:** `packages/utils/src/system-custom-error.js` provides the single native-Error base. Its tests cover concrete subclass identity, native `cause` identity (including non-Error causes), stable code, frozen scalar context, retryability and invalid options.
- **Package-owned examples:** DB `DatabaseProviderError` normalizes provider failures and preserves causes, including multiple backup/cleanup failures via `AggregateError`. Brokers `BrokerUnsupportedOperationError` has a stable code and explicit non-retryable classification. Provider-local `BinanceRpcError` subclasses retain request, method, status and cause details and mark dispatched mutations with unknown outcomes; protocol tests cover timeout, dispatch uncertainty and observer-failure isolation. These transport-specific types remain inside the provider adapter rather than becoming a workspace-wide error contract. The public Broker API distinguishes `NOT_SENT` from `OUTCOME_UNKNOWN` and prohibits blind retries of unknown mutations.
- **Harvester examples:** Recovery Seller reconciliation and legacy Spot allocation use feature-owned codes and fail-closed checks; operator-query and operational-state tests verify cause preservation and reject incomplete/invalid snapshots instead of returning partial healthy state. The operator error vocabulary remains the operator-facing symptom/recovery reference.
- **Adoption gap:** older feature-owned errors still directly extend native `Error` (including operator-query, market-readiness, trading-session, Telegram configuration/startup and process operational-state errors). Existing paths have tests, but the adoption is not uniform and no repository-wide scanner enforces it. This is not authority for a blanket conversion; #1028 remains the incremental owner-coordinated migration.
- **Decision:** retain one canonical standard and the existing base. S-4 adds conceptual failure categories without a universal category property, clarifies retry ownership and idempotency, distinguishes known failures from unknown outcomes, defines safe fallback versus fail-closed behavior, and strengthens logging/reporting and test expectations. No runtime behavior, package API, CI workflow or exchange operation is changed in this phase.

**Status:** S-4 policy extension merged in [PR #1579](https://github.com/45s/coinzilla/pull/1579) at `659493ca23792e1ac339de7102e3cebb4d377cba`. Gradual adoption of legacy error subclasses remains owner-coordinated under [#1028](https://github.com/45s/coinzilla/issues/1028).

## S-5 verified findings — 2026-11-20

- **Shared API already exists:** `packages/utils/src/logger.js` exports `Logger` and `defaultLogger`; package docs/tests cover structured records, severity thresholds, independent transports, process context, normalization/redaction, failure isolation and cleanup. No logger wrapper or new shared API is justified.
- **Consumer ownership:** Harvester uses the shared logger and owns its operational event vocabulary, terminal presentation, session files and retention decisions. Correlation IDs are attached to individual operation/event data. The process-wide Logger context is used for stable process identity; changing it per concurrent request would create shared-context races.
- **Confirmed fallback leak:** the default transport-error reporter and the emergency fallback after a custom reporter failure previously wrote raw Error objects to stderr. Error messages/stacks are not content-redacted by the structured formatter. S-5 adds regression tests and a bounded fallback that emits only transport identity and safe error type; the custom `onTransportError` callback still receives the original error.
- **Test-first evidence:** the isolated regression tests failed on test-only commit `6279998c4759306f19947c5ef4be712d977686eb` for both synthetic secret-leak cases. The implementation commit `2d7140ed7b365fff0eb5d794f98b9da6425f8987` passed the Utils unit-test workflow (241 tests: 239 passed, 0 failed, 2 skipped), and the Utils package coverage workflow passed. On the pre-sync PR head `a896bf840d868f0a0b4387f2bcf5acd179c555c8`, all six required status contexts and all seven PR workflow runs completed successfully; one read-only Binance TESTNET integration was skipped by policy. These results do not validate the synchronized merge head; all required checks must be rerun on that exact head before review.
- **Scope decisions:** no Harvester source changes, application-local logger, implicit async-context propagation, generic metrics/tracing framework, new CI scanner, or shared log-retention policy. The fatal `process.stderr.write` audit remains separate; #1264 owns additional CI/security enforcement.

## S-0 findings and decisions

1. **The repository already has a strong canonical foundation.** Engineering, documentation, modularity, shared utilities, JavaScript/JSDoc, ESLint, structured errors, task workflow and domain ownership each have an identifiable source. Keep these sources; do not create replacement policy documents.
2. **Configuration standard — established in S-3.** The canonical standard defines ownership, loading/validation boundaries, defaults, environment access, read-only runtime snapshots, secret handling, compatibility and tests. The confirmed Harvester import-time environment read was removed. No broad AST enforcement was added because legitimate CLI/bootstrap/utility environment access requires explicit boundary-aware exceptions.
3. **Naming and file-tree guidance is partial, not absent.** The Modularity Standard covers feature placement and helper boundaries; S-7 should fill only the responsibility/naming gaps demonstrated by source.
4. **Architecture enforcement must be coordinated.** Package manifests provide a clear declared dependency graph; package-specific checks and #1565 already exist or are in progress. S-1/S-9 must inspect and reuse them before proposing a repository-wide checker.
5. **Testing CI covers all nine workspace packages, but package-specific thresholds are not uniform.** Entities has no dedicated threshold script. S-2 should define the standard; #1264 owns matrix/CI enforcement and package owners own their thresholds.
6. **AI workflow preflight is now canonicalized.** Merged PR #1569 adds `AI_TASK_COMPLIANCE_STANDARD.md` and links it from root AGENTS, AI workflow, task workflows, docs index and PR template. S-6 should audit for remaining conflicts rather than recreate the gate. #1401 and #1403 remain the factual and reference-tracing workstreams. The last recorded 160-path documentation inventory is historical relative to this baseline and must not be repeated as a current count without a fresh complete tree scan.
7. **No obsolete canonical standard was confirmed in the S-0 scope.** Any retirement or consolidation must be supported by the reference-tracing process in #1403.
