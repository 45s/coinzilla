# Harvester Audit Working Rules

These collaboration rules apply to the Conservative Strategy Audit and all contributors/agents working in parallel.

1. **Update shared records immediately.** After every useful operator-provided fact, evidence, clarification, or policy decision, update the affected documentation and GitHub issue/PR records in the same work session. Do not defer recording until the end of the audit.
2. **Keep documents synchronized.** Update every affected source of truth (including the roadmap, domain specification, accounting invariants, audit findings, acceptance criteria, and relevant issue/PR descriptions or comments). Clearly mark superseded statements; do not leave contradictory current guidance.
3. **Verify before claiming.** Report a GitHub/document update as complete only after the write succeeds. If another contributor changed the same file/branch or an update cannot be made safely, report the exact blocker and do not overwrite their work.
4. **Keep operator communication concise and conversational.** Give the immediate result, important implication, and only the next necessary question. Do not dump long reports or large lists unless requested.
5. **Clarify on request.** If the operator asks for a rephrase or clarification, explain only the requested point in plain language.
6. **Preserve decisions and rationale.** Once the operator makes a policy decision, record the exact decision, rationale, affected requirements, and status in the relevant shared records. Do not reopen settled decisions without new evidence or an explicit request.
7. **Respect parallel work.** Shared documentation is operational coordination. Check the latest branch/file state before editing, make narrow changes, and avoid replacing unrelated content.

These rules govern collaboration and documentation hygiene; they do not silently resolve technical or trading-policy questions.
